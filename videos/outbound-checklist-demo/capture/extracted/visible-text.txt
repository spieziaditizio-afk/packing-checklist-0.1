DOMAIN MODEL
A delivery has: operator, delivery#, Pick Label PN, destination (Europe ≤180cm
/ Export ≤160cm height limit). Each pallet has: type (KP/EP/BP/GP/NP/AP →
dimensions), weight, height, plus two sub-sections:
1. Pick Labels — target quantities (sum of Pick 1, Pick 2… rows = target
   pieces for the pallet).
2. Box Verification — actual verified quantities, scanned per box in Scan
   mode (one shared PN field + per-box qty rows).

The validation strip at the bottom of each pallet aggregates: Pick PN | Box PN
| PN Check | Target (pcs) | Verified (pcs) | Boxes, plus a status badge:
PENDING / ✓ MATCH / ✗ MISMATCH.

SIGNATURE FEATURES (what the video should demonstrate)
1. Central scan pipeline — every scannable field accepts Enter or Tab (Zebra
   DS3678 scanner or typed input, treated identically); a green flash + beep
   confirms every valid scan.
2. Live Box Progress bar — per pallet, fills live as boxes are verified
   against the Pick Label target; color states sweep idle → low → mid → high
   → done (green completion pulse).
3. Continuous cross-pallet scanning — the moment a pallet's Box Verification
   total reaches its Pick Label target, focus automatically switches to the
   next pallet's tab and scan field, with no mouse clicks — an operator can
   scan an entire delivery front to back without touching the computer to
   pick each pallet manually.
4. Over-target hard stop (the standout feature) — scanning past the target is
   a hard stop, not a warning: the field flashes red, a centered toast reads
   "⚠ OVER TARGET — N pcs over target", and the run freezes so the operator
   can find the double-scanned box immediately, not several pallets later at
   print time.
5. Validation strip — per pallet: Pick PN | Box PN | PN Check | Target |
   Verified | Boxes, plus the MATCH/MISMATCH/PENDING badge.
6. Multi-session — each delivery is its own session (URL hash #s=<id>); an
   Order History dropdown lists/switches/deletes saved orders; "New Order"
   flushes the current session and jumps to a fresh blank one.
7. Random PN Audit — a standalone 🎲 modal for spot-checking random boxes
   against the reference PN, independent of pallet state.
8. Print / export — a validation-complete delivery produces a print-ready
   report (browser print → PDF), one row per pallet with Pick Label
   breakdown, Box Verification detail, and the summary/status table.
9. Architecture callout — the whole app is a single ~2200-line HTML file:
   double-click to open in Chrome, no server, no build step, no node_modules;
   state persists in localStorage per session.
